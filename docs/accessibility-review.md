# Accessibility review checklist

## Purpose

Check keyboard focus, screen reader labels, 200% zoom, contrast, reduced motion, and accessible errors for six chart cards. This is a checklist, not a claim of compliance.

## Review procedure

1. Verify the current production site behavior before changing code.
2. Record test conditions, including browser, device, and date.
3. Check the relevant user flows against the criteria above.
4. Document actual failures and fixes in a dedicated issue or pull request.
5. Review the diff for personal information, secrets, and broken links.
6. Confirm the GitHub Pages deployment after merging.

This document is a review guide, not evidence that the listed checks have passed.
